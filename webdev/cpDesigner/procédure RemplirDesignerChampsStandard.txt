// ─────────────────────────────────────────────────────────────────────────────
// cpDesigner.RemplirDesignerChampsStandard
// Rôle : Construire le tableau des champs de fusion "standard" disponibles
//        pour la modale "Ajouter un champ" du Designer (onglet Standard).
//        Permet à l'utilisateur d'ajouter en un clic (ou un double-clic
//        depuis V2.4) un champ courant (Nom, Prénom, Code postal, etc.)
//        avec son nom technique, son libellé, son type, et désormais
//        sa VALEUR PAR DÉFAUT (placeholderDefaut V3.6).
//
// V3.6 (19/05/2026) — Refonte complète selon la liste métier réelle
// Marketeam (cf. docs/cahier_des_charges_creation_champs_fusion.md V2.4
// §5.1bis et amendement V2.4 §2.4). L'ancienne liste (V3.4/L1) contenait
// des entrées inadaptées (« N° Client », « Logo entreprise », « Photo
// contact ») qui ne correspondaient pas au métier — bug A11 corrigé.
//
// Champs métier Marketeam (18 entrées) :
//   - Identité destinataire : Civilité, Nom, Prénom, Société, Enseigne,
//     Contact, Référence
//   - Adresse postale : Adresse 1 à 4, Code postal, Ville, Pays
//   - Coordonnées : Téléphone, Portable, Email
//   - Métier La Poste : Code Alliage (NPAI)
//
// Pour chaque champ, on transporte aussi un placeholderDefaut (V3.6) :
// valeur d'exemple métier utilisée par l'algorithme unifié de résolution
// d'échantillon côté Designer (cf. cahier V2.4 §7.3.2 étape 4) quand
// l'utilisateur ne saisit pas de valeur perso et qu'aucune valeur n'est
// disponible dans la fiche utilisateur (donneesApercu).
//
// IMPORTANT : pour les champs créés via cette liste, le 'nom' technique est
// TOUJOURS renseigné. Côté Designer, le champ est considéré comme :
//   - origine = "ajout" (V2.4) car ajouté par l'utilisateur via la modale
//     → librement modifiable et supprimable
//   - categorie = "standard" (V2.4) → onglet Standard figé en édition
//
// Codes types utilisés (cf. constantes WebDev) :
//   __CHAMP_TYPE_TEXTE__       (TXT)
//   __CHAMP_TYPE_CODEPOSTAL__  (CDP) pour Code postal
//   __CHAMP_TYPE_EMAIL__       (EML) pour Email
//   __CHAMP_TYPE_TELEPHONE__   (TEL) pour Téléphone
//   __CHAMP_TYPE_PORTABLE__    (SMS) pour Portable
//
// Appelée par :
//   - cpDesigner.ComposerJsonDesignerCreation (tunnel courrier)
//   - cpDesigner.ComposerJsonDesignerModele (création / édition modèle)
//
// Paramètre :
//   pIdClient (entier) : identifiant client (réservé usage futur — par
//                        exemple pour aller chercher une liste différente
//                        dans prm_designer_champs_standard si un client a
//                        des standards spécifiques). Conservé en signature
//                        car appelé par les deux procédures ci-dessus.
//
// L17/A27 (Correction 2) — placeholderDefaut personnalisé à la fiche
//   utilisateur. La fiche `Partage.__vcUser.stCoordonnées` est une
//   `StructBaseLigne`, symétrique aux enregistrements standards de la base.
//   Elle expose les membres : Civilite, Nom, Prenom, Societe, Enseigne,
//   Contact, Reference, Adresse1-4, CodePostal, Ville, Pays, Tel,
//   Portable, Email, CodeAlliage.
//
//   Pour chaque champ standard, le placeholderDefaut prend désormais la
//   valeur de la fiche utilisateur SI elle est non vide, sinon retombe sur
//   le placeholder générique métier (ancienne valeur V3.6).
//
//   Bénéfices :
//   - À la création d'un modèle, le pré-remplissage automatique de
//     l'échantillon (algo unifié V2.4 §7.3.2 étape 4a) reprend les vraies
//     coordonnées de l'utilisateur connecté → modèle plus réaliste.
//   - Combiné à L17/A27 Correction 1 (inversion priorité dans
//     SelectionModèle/btnDocumentPersonnaliser), évite les écrasements
//     ATTALI → Dupont du pavé adresse.
//
//   Helper interne `PlaceholderOuDefaut` factorise le pattern
//   « si fiche non vide → fiche, sinon → défaut » pour les 18 entrées.
//
// Retour :
//   tableau de structDesignerChampStandard (sérialisé sous "champsStandard"
//   en racine du message load).
// ─────────────────────────────────────────────────────────────────────────────
procédure RemplirDesignerChampsStandard(pIdClient <utile>) : tableau de structDesignerChampStandard

stUnChamp			est une structDesignerChampStandard

//     - fiche utilisateur `__vcUser.stCoordonnées.Tel`
