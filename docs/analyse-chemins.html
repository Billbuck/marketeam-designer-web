1. Image de fond enveloppe
ComposerJsonDesignerCreation()
Le PDF de fond de l'enveloppe est lu depuis le catalogue :
__sRepRacine + "Enveloppes\" + FichierApercu + .pdf
Pas de souci : c'est un fichier fixe du catalogue, independant de l'operation.
2. Generation du PSMD enveloppe
GenererPsmdServeurEnveloppe()
Le JSON temporaire et le .psmd sont ecrits dans :
__sMarketeamRepRacine + __sRepUpload + "\"
Nom : __DOC_ENV_PSMD__ + CodeTemp + ".psmd"
En creation, CodeTemp = horodatage. Tout est dans Upload Marketeam. OK.
3. Generation du BAT enveloppe (JPG)
GenererBatEnveloppeDepuisPsmd()
Le JPG est genere dans :
__sMarketeamRepRacine + __sRepUpload + "\" + __DOC_ENV_BAT__ + CodeTemp + .jpg
Le PSMD est lu depuis le meme endroit. Coherent.
4. Sauvegarde + rangement
DéplaceFichierUpload()
Le BAT enveloppe est deplace vers :
CheminFichier(IdOperation, __REP_BAT__) + __DOC_ENV_BAT__ + IdOperation + .jpg
Tout va bien : le fichier quitte Upload pour le dossier operation.
1. Rechargement de l'enveloppe
ChargeStructOperationLettre()
Le BAT est charge depuis :
CheminFichier(IdLettre, __REP_BAT__) + __DOC_ENV_BAT__ + IdOperation + .jpg
Le fond depuis :
CheminFichier(IdLettre, __REP_FOND__) + __DOC_ENV_FOND__ + IdOperation + .jpg
Les fichiers sont bien sous le dossier operation. OK.
2. Test d'existence du fond enveloppe
ChargeStructOperationLettre() — ligne ~1628
Le fond est teste avec le chemin relatif :
fFichierExiste(sFondCheminRelatif + __DOC_ENV_FOND__ + …)
Alors que le BAT est teste avec le chemin physique :
fFichierExiste(sBatCheminPhysique + __DOC_ENV_BAT__ + …)
INCOHERENCE Un chemin relatif (URL) passe dans fFichierExiste qui attend un chemin disque.
3. L'utilisateur re-personnalise l'enveloppe
GenererPsmdServeurEnveloppe()
Le nouveau PSMD est genere dans :
__sMarketeamRepRacine + __sRepUpload
Mais les fichiers de l'operation vivent maintenant dans :
CheminFichier(IdOperation, __REP_*__)
CONFLIT Le PSMD est ecrit dans Upload alors que tout le reste est dans le dossier operation.
4. Generation du BAT enveloppe
GenererBatEnveloppeDepuisPsmd()
Le JPG BAT est genere dans :
__sMarketeamRepRacine + __sRepUpload + __DOC_ENV_BAT__ + CodeTemp + .jpg
Mais au rechargement le BAT est attendu dans :
CheminFichier(…, __REP_BAT__) + __DOC_ENV_BAT__ + IdOperation + .jpg
CONFLIT Le BAT est genere au mauvais endroit avec potentiellement le mauvais nom.
5. Re-sauvegarde
DéplaceFichierUpload()
DéplaceFichierUpload deplace le BAT depuis EnveloppeBAT.CheminPhysique.
Si ce chemin pointe encore vers Upload (ecrit a l'etape 4) : OK — le deplacement fonctionne.
Mais si EnveloppeBAT.CheminPhysique pointe deja vers ROP (rechargement sans re-personnalisation) et qu'on tente de le deplacer sur lui-meme...
RISQUE Depends de l'etat memoire vs disque.

5. Generation BAT (JPG)

DéplaceFichierUpload()
PDF, BAT, fonds sont deplaces de Upload vers

Noms convertis de CodeTemp vers IdLettreContenu. OK.

Mais le PSMD et le JSON temp Node restent dans Upload (non deplaces).
1. Rechargement du document
ChargeTabStructLtrDocument() + ChargeDocument()
CodeTemp = IdLettreContenu
Repertoire = probablement CheminFichier(IdOperation, __REP_DOCUMENT__)
NomFichierTemp = __DOC_LTR__ + IdLettreContenu + .pdf
Les fichiers vivent dans le dossier operation. Coherent.
2. L'utilisateur re-personnalise le document
GenererPsmdServeurDocument()
Le code construit :
sRepUpload = __sMarketeamRepRacine + __sRepUpload
sCheminPsmd = sRepUpload + __DOC_LTR_PSMD__ + CodeTemp + ".psmd"

Le PSMD est ecrit dans Upload, pas dans le dossier de l'operation ou le PDF vit.
CONFLIT MAJEUR Le repertoire de travail est toujours Upload, independamment du contexte creation/modification.
3. Generation BAT document
GenererBatDocumentDepuisPsmd()
Les JPG BAT sont generes dans :
__sMarketeamRepRacine + __sRepUpload + __DOC_LTR_BAT__ + CodeTemp + p1.jpg…

Le rechargement attend les BAT dans :
CheminFichier(IdOperation, __REP_BAT__) + __DOC_LTR_BAT__ + IdLettreContenu + p1.jpg…
CONFLIT MAJEUR BAT genere dans Upload au lieu du dossier operation.
4. Appel PSM PHP pour generer le BAT
GenerationBatDepuisPsmd() → psm_marketeam_jpg.php
Le PHP recoit en parametre p = chemin du PSMD
Ce chemin pointe vers Upload.
Le PSMD, lui, reference potentiellement des images de fond qui vivent dans ROP.
CONFLIT Le PSMD dans Upload peut contenir des chemins vers des fichiers dans le dossier operation, ou inversement.
5. Vignettes fond si re-upload
GenereVignetteDocument()
Genere toujours dans :
__sRepRacine + __sRepUpload
Code en dur : pas de parametrage du repertoire de sortie.
Si le PDF est dans ROP, Ghostscript cherche dans Upload...
CONFLIT Sauf si le PDF est recopie dans Upload pour la circonstance.
6. Normalisation BleedBox
UploadFichier() — appel PyMuPdf
Utilise stDocument.Repertoire + stDocument.NomFichierTemp
Si Repertoire a ete mis a jour vers ROP par ChargeDocument, c'est OK.
Sinon c'est Upload et le PDF n'est plus la.
DEPENDS de ce que fait ChargeDocument (code absent).
7. ComposerJsonDesignerCreation (fonds dans le JSON)
ComposerJsonDesignerCreation() — ligne ~2789
Le chemin du PDF fond dans le JSON Designer est construit avec :
stDoc.Repertoire + stDoc.NomFichierTemp
Les images de fond viennent de stDoc.tabImageFond.
DEPENDS Si ces membres pointent encore vers Upload alors que les fichiers sont dans ROP...

Resume : 7 conflits rouges, 4 risques oranges

Conflits certains (en modification)

  • GenererPsmdServeurDocument — PSMD ecrit dans Upload au lieu du dossier operation
  • GenererPsmdServeurEnveloppe — Idem pour le PSMD enveloppe
  • GenererBatDocumentDepuisPsmd — JPG BAT genere dans Upload au lieu de __REP_BAT__
  • GenererBatEnveloppeDepuisPsmd — Idem pour le BAT enveloppe
  • GenerationBatDepuisPsmd → PHP — Le PSMD passe a PSM peut referencer des fichiers dans le mauvais repertoire
  • GenereVignetteDocument — Repertoire d'entree/sortie code en dur sur Upload
  • DéplaceFichierUpload — Les fichiers PSMD ne sont jamais deplaces ni nettoyes

Risques conditionnels

  • ChargeStructOperationLettre — Test fFichierExiste sur chemin relatif (URL) au lieu de physique pour le fond enveloppe
  • ComposerJsonDesignerCreation — Chemins des fonds dans le JSON Designer depends de Repertoire et tabImageFond
  • Normalisation BleedBox — Le chemin passe a PyMuPdf depend de stDocument.Repertoire
  • DéplaceFichierUpload (re-sauvegarde) — Si les fichiers sont deja au bon endroit, le deplacement peut echouer ou etre un no-op
